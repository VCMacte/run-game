# Снять замеры с телефона

Журнал забега — единственный свидетель того, как игра ведёт себя на ребёнке.
Числа телеграфа и скоростей в `js/config.js` до сих пор **оценки**, и
пересчитать их можно только отсюда. Этот ритуал превращает полмегабайта JSON в
несколько чисел и говорит, какие из них к чему ведут.

Читать журнал глазами нельзя: в одном файле до двадцати сессий, и интересная —
не первая.

## 1. Достать файл с телефона

На телефоне: родительское меню (**долгое удержание правого верхнего угла**) →
«Журнал событий» → «Выгрузить файлом». Файл называется
`run-game-log-<дата>-<время>.json`.

Положить в `logs/`. Содержимое этой папки в репозиторий не уезжает намеренно —
репозиторий публичный, а журнал — запись о том, как и когда ребёнок играл в
своей комнате. Это не формальность: следи за ней на каждом шаге ниже.

## 2. Прогнать разбор

```
node tools/log-report.mjs logs/run-game-log-2026-10-06-18-19-23.json
```

Печатает сводку по **каждой** сессии файла. Короткие сессии на несколько
записей — это открытия приложения без забега, их можно пролистать; смотреть
надо те, где есть строка «забег» либо поток ошибок.

Разбор — чистая функция, проверенная группой «разбор журнала» в
`tests-control.mjs`. Если правишь его, правь сначала проверку: набор печатает
число проверок, и прирост виден.

## 3. Прочитать числа

| Что в сводке | К чему ведёт |
|---|---|
| `позы N Гц (цель 20)` | достижимая частота. Ниже цели — упирается в инференс, а не в арт: сравни с медианой инференса, `1000 / p50 ≈ Гц` |
| `инференс: медиана окон` | главный бюджет кадра. От него зависят `OBSTACLES.signalS`, `minLeadS` и `VIEW.speed`: окно решения не может быть короче задержки ответа |
| `худшее окно по p95` | провалы. Если худшее втрое больше медианы — ищи, что ещё грузит GPU, прежде чем менять числа |
| `отрисовка` рядом с инференсом | кто кого ждёт. Отрисовка в единицы миллисекунд при инференсе в десятки означает, что виноват не арт |
| `делегат` + `прогрев p50` | заявленный делегат умеет врать; честный ответ даёт только время прогрева |
| `колец N/M (X%)` | сложность сбора. Высокий процент — поле и `VIEW.starX`/`starReach` достижимы |
| `препятствия: чисто / прощено / задето` | щадящесть. Много прощённых — `OBSTACLES.lateForgiveMs` работает; много задетых — телеграф не читается |
| `не задето X%` | сложность уклонения. Выше 95% — мерить сложность не на ком, надо усложнять |
| `паузы: N эпизодов, X с (Y% забега)` | сколько забега съедено не игрой. Разбивка по причине важнее доли |
| `scale` среди причин | пороги присутствия: `SIGNALS.scaleMin`, `scaleRelMax` |
| `edge` среди причин | ребёнок вываливается из кадра, дотягиваясь: `VIEW.starX`, `starReach`, `panGain` |
| `ошибки: N за X с` | дефект. Длительность важнее числа: «упало 1478 раз за 133 с» — это замерший экран, а «1478 раз за 2 с» — одна вспышка |
| `ширина поля panSpan` | размах игрока из калибровки. Нет его — журнал снят до нормировки поля, и сравнивать `u` с другим забегом нельзя |

## 4. Записать результат

Положить сводку в `measurements/run-<дата>-<время>.md` — блок готовит
`markdown()` из того же модуля — и дописать раздел «Что из этого следует»: какие
числа в `js/config.js` меняются и почему. Без этого раздела файл бесполезен:
через месяц сводка без вывода не отличается от сводки, по которой ничего не
сделали.

**В `measurements/` уезжают только агрегаты** — герцы, миллисекунды, доли.
Никогда `samples` и `skeleton`: это записанные движения ребёнка, а папка
попадает в публичный репозиторий. Разбор их и не печатает, но если выписываешь
числа руками — помни.

Правку `CLAUDE.md` делать руками и отдельно: раздел «Состояние» — один факт в
одном месте, и автоматическая перезапись развела бы числа по двум файлам.

## Ловушки, на которых разбор уже ошибался

**Склейка повторов.** Журнал сворачивает одинаковые события подряд в одну
запись со счётчиком `_n`. Одна запись может означать 1478 событий. Но склейка
появилась **позже самих журналов**: все снятые с телефона файлы несут поток
отдельных записей. Поэтому разброс потока считается по группе одинаковых
событий, от первой отметки до последней, а не внутри записи. Пока он считался
внутри записи, настоящий журнал печатал «1478 ошибок за 0 с» вместо 133 секунд
замершего экрана.

**Квантили в `health` посчитаны внутри окна.** Усреднять их нельзя: среднее
квантилей — не квантиль. Сводка поэтому говорит «медиана окон» и «худшее окно
по p95», а не «p50 забега». Из этих данных p50 по всему забегу не получается, и
писать его в `measurements/` значило бы соврать числом.

**`u` значит разное в разных событиях.** В `health` — доли игрового поля, в
`gesture` — длины торса. Сравнение ребёнка со взрослым строится ровно на этих
числах, и перепутать их легко.

**Забег без `run.finish` брошен.** Считать его забегом с нулём колец нельзя —
та же логика, по которой в таблицу рекордов попадает только дошедший до финиша.

**Пауза без `resume` — это пауза, из которой не вышли.** Она считается до конца
журнала, и большое число здесь не ошибка разбора, а описание того, что сеанс
кончился на паузе.

## Чего этот ритуал не делает

Не судит, весело ли. Доля колец и число пауз не говорят, понравилось ли ребёнку;
это проверяется только прогоном с ним. Замер отвечает на вопрос «подтвердились
ли оценки», а не «хорошая ли игра».

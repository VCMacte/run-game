# Кубок, этап 6 — вершина

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Двенадцатый уровень перестаёт быть обещанием: на 1200 кольцах кубок
золотеет, кольца становятся радужными, а финиш получает свою фанфару. Лестница
закрыта целиком.

**Architecture:** Вершина — это НЕ новая подсистема, а три мелких изменения в
уже существующих местах: заливка полос кубка на экране, цвет колец в забеге и
подмена мотива финиша. Ни одной новой формы, ни одного нового экрана. Самое
тонкое — радужные кольца: кольцо это цвет РЕШЕНИЯ, и свободный цвет ему не
положен ни в каком призе, поэтому «радуга» делается сменой ОТТЕНКА внутри
контракта светлоты, а не произвольной палитрой.

**Tech Stack:** Голые ES-модули. Тесты — `node tests-shell.mjs`,
`node tests-control.mjs`. Проверка кадром — `tools/frame.html?prizes=all`.
Кэш — `node tools/make-sw.mjs`.

**Спек:** [`../specs/2026-10-16-trophy-and-worlds-design.md`](../specs/2026-10-16-trophy-and-worlds-design.md)

## Что известно до начала работы

**Спек описывает вершину одной строкой:** «Золотой кубок — кубок золотеет,
радужные кольца, своя фанфара». Это три разных места, и каждое упирается в своё
правило:

- **Кубок золотеет** — экран, половина палитры ЛИСТОВ. Контракт
  `DECISION`/`BACKGROUND` сюда не распространяется, но различимость светлотой
  под Miracast остаётся, и светлота полос обязана строго возрастать с зазором
  0.04. Двенадцатая полоса уже самая светлая (`#fff4d2`, 0.906) — «золотеет»
  означает обводку и смену оттенка остальных полос, а не новый цвет вершины.
- **Радужные кольца** — цвет РЕШЕНИЯ. Светлота `star` и `starDim` проверяется
  по каждой зоне, и свободного цвета кольцу не положено. Значит радуга — это
  медленная смена ОТТЕНКА при той же светлоте.
- **Своя фанфара** — звук. Словарь не растёт: подмена мотива `finish`, как уже
  сделано для приза уровня 4. Вариант вершины обязан быть длиннее фанфары
  уровня 4 и оставаться самым длинным мотивом.

**Бюджет кадра не меняется.** Ни одна из трёх правок не добавляет заливок:
кубок — экран, кольца — другой цвет той же фигуры, фанфара — звук.

## Global Constraints

- **Вершина — уровень 12 (1200 колец)**, `TROPHY[11]`, id `gold`.
- **Кольцо — цвет РЕШЕНИЯ.** Светлота `star`, `starDim`, `starBig`,
  `starBigDim` проверяется контрактом по каждой зоне; приз не вправе её menять.
- **Цвета решения одинаковы во всех зонах ПОБАЙТОВО** — радуга обязана быть
  общей для всех зон, иначе зона перекрасит язык игры.
- **Словарь звука не растёт**: вершина подменяет мотив `finish`, а не заводит
  новое событие. Число вступлений может расти только у финиша.
- **Ноты не наезжают**: `notes[i][1] >= notes[i-1][1]`.
- **Светлота полос кубка строго возрастает с зазором 0.04.**
- **Худший кадр 118 при потолке 150 и мягком рубеже 120** (или то, что скажет
  этап 5); две копии числа сверяются ТОЧНЫМ равенством. Этап не должен его
  менять — если изменил, это находка.
- **Анимации — функции времени с фазой, состояние не копят**; амплитуда жмётся
  `motionScale`, но не в ноль.
- **Приз проверяется КАДРОМ, а не только счётчиком.**
- **Правка кода и документации едут ОДНИМ изменением.**
- **Не больше четырёх параллельных процессов.**

## Review Focus

1. **Радуга не вправе сломать контракт светлоты** — `star` и `starDim` обязаны
   остаться в тех же границах по каждой из двенадцати зон, в любой фазе радуги.
   → Задача 2.
2. **Радуга одинакова во всех зонах** — цвет решения побайтово общий, иначе
   зона перекрашивает «иди сюда». → Задача 2.
3. **Фанфара вершины остаётся самым длинным мотивом** и не наезжает нотами.
   → Задача 3.
4. **Приз не открыт** — кубок, кольца и финиш обязаны выглядеть ровно как до
   вершины: ни одного отличия при `gold: false`. → Задачи 1–3.
5. **Копилка ВЫШЕ вершины** (2000, 100000) — ничего не ломается, уровень
   зажат двенадцатью, радуга идёт как на 1200. → Задача 1.

- [ ] **Step 4: Функция оттенка**

В `js/view.js`, рядом с `rgba`:

```js
/** Тот же цвет с ПОВЁРНУТЫМ оттенком и ТОЙ ЖЕ светлотой. Радуга вершины
    красит кольцо, но кольцо — цвет РЕШЕНИЯ, и контракт светлоты на него
    распространяется в любой фазе: свободного цвета ему не положено ни в каком
    призе. Поэтому поворачивается ТОН (через HSL), а светлота возвращается на
    место подбором множителя.

    Замерено на `#ffd34d`: максимальное отклонение светлоты за оборот 0.0048
    при допуске 0.02, двенадцать различимых цветов за период. */
export function rainbowOf(base, t, scale = 1) {
  const r = parseInt(base.slice(1, 3), 16) / 255;
  const g = parseInt(base.slice(3, 5), 16) / 255;
  const b = parseInt(base.slice(5, 7), 16) / 255;
  const max = Math.max(r, g, b); const min = Math.min(r, g, b);
  const l = (max + min) / 2;
  let h = 0; let s = 0;
  if (max !== min) {
    const d = max - min;
    s = l > 0.5 ? d / (2 - max - min) : d / (max + min);
    h = max === r ? ((g - b) / d + (g < b ? 6 : 0)) : max === g ? ((b - r) / d + 2) : ((r - g) / d + 4);
    h /= 6;
  }
  h = (h + (t * MOTION.rainbowHz * scale) % 1 + 1) % 1;
  const тон = (p, q, x) => {
    let v = x; if (v < 0) v += 1; if (v > 1) v -= 1;
    if (v < 1 / 6) return p + (q - p) * 6 * v;
    if (v < 1 / 2) return q;
    if (v < 2 / 3) return p + (q - p) * (2 / 3 - v) * 6;
    return p;
  };
  const q = l < 0.5 ? l * (1 + s) : l + s - l * s;
  const p = 2 * l - q;
  const к = [тон(p, q, h + 1 / 3), тон(p, q, h), тон(p, q, h - 1 / 3)];
  const hex = (a) => '#' + a
    .map((v) => Math.max(0, Math.min(255, Math.round(v * 255))).toString(16).padStart(2, '0'))
    .join('');
  /* Светлота возвращается на место двоичным поиском множителя: поворот тона
     её сдвигает, а контракт этого не прощает. Двадцать четыре шага дают
     точность заведомо выше допуска. */
  const цель = luminance(base);
  let lo = 0; let hi = 3;
  for (let i = 0; i < 24; i++) {
    const m = (lo + hi) / 2;
    if (luminance(hex(к.map((v) => v * m))) < цель) lo = m; else hi = m;
  }
  return hex(к.map((v) => v * (lo + hi) / 2));
}```

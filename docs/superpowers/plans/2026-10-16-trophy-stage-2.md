# Кубок, этап 2 — дешёвая косметика

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Четыре из пяти уровней лестницы между мирами перестают быть обещанием:
обочина расцветает (200), финиш получает фанфару (400), кольцо — ободок (500),
ночная зона — светлячков (700), а сбор кольца — послезвучие (800).

**Architecture:** Ни один приз не заводит новой подсистемы. Звук получает
таблицу ВАРИАНТОВ мотива (`VARIANTS` в `js/audio.js`): приз подменяет мотив
того же события, не добавляя нового. Обочина получает единственного владельца
состава видов — `kindsFor(zone, prizes)` в `js/theme.js`, который отбирает виды
по призу и подменяет веса; второго списка видов не появляется. Ободок живёт в
той же ветке `drawStars`, что искры.

**Tech Stack:** Голые ES-модули без сборщика и без зависимостей. Тесты —
обычные скрипты `node` (`node tests-shell.mjs`, `node tests-control.mjs`), без
раннера. Офлайн-кэш и версия генерируются `node tools/make-sw.mjs`.

## Три поправки к спеку, найденные до начала работы

Спек — документ замысла, и три его оценки оказались неверны. Правки внесены
здесь; спек править не нужно — план и есть то место, где его аргумент
уточняется.

**«Звонкий сбор — мотив `star` в три ноты» СТОЛКНУЛСЯ БЫ с `starBig`.** Мотивы
в этом проекте различаются ЧИСЛОМ нот, а не высотой (высоту съедает телефонный
динамик и комнатное эхо), и `starBig` — это ровно три ноты. Приз в три ноты
сделал бы обычное кольцо неотличимым от большого, то есть отнял бы у ребёнка
единственный признак награды. Аккорд тоже закрыт: группа «звук» требует, чтобы
ноты не наезжали, и объясняет почему — «мотив превращается в аккорд, и ритм,
которым они различаются, пропадает». Остаётся ДЛИТЕЛЬНОСТЬ: приз даёт те же две
ноты с послезвучием. Число вступлений не меняется.

**«Цветущая обочина — 0 заливок» неверна в лучшую сторону: она их
ОСВОБОЖДАЕТ.** Виды стоят по-разному — `palm` 3 заливки, `bush`, `flower`,
`cactus`, `spruce`, `post`, `totem` по 2, `rock` 1. Смещение веса с пальмы на
цветок и куст делает кадр ДЕШЕВЛЕ, и именно этим платится ободок. Порядок задач
из-за этого обязателен: сначала обочина, потом ободок.

**«Ободок — 0, замена» неверна: это +1 заливка.** Кольцо сейчас две заливки —
тело и внутреннее отверстие (`ring(w, r, colr)` и `ring(w*0.42, …, colDim)`);
третий контур добавляет третью. Платится он обочиной, и плата идёт ПЕРВОЙ.

## Global Constraints

- **Шаг лестницы — 100 колец, уровней 12, вершина 1200.** Миры на 300, 600, 900
  (этапы 3 и 5, здесь не трогаются).
- **Ни один приз не меняет приговор:** ни расстановку, ни пороги, ни телеграф,
  ни ступень сложности, ни словарь управления (шаг в сторону и присед).
- **Словарь звука не растёт.** Новый МОТИВ означал бы новое действие. Призы
  подменяют существующие мотивы того же события; число вступлений у подмены
  обязано совпадать с базовым, кроме финиша, который и так самый длинный.
- **Ноты не наезжают.** `notes[i][1] >= notes[i-1][1]` и, по смыслу абзаца в
  группе «звук», одновременных нот не бывает — аккорд убивает ритм.
- **Косметика заменяет, а не добавляет.** Худший кадр **116 при потолке 150 и
  мягком рубеже 120**; добавляющий приз оплачивается ЗАРАНЕЕ, ручка —
  `DECOR.gapS` либо состав видов обочины.
- **Две копии числа худшего кадра** (`CLAUDE.md` и счётчик в группе «бюджет
  кадра») сверяются ТОЧНЫМ равенством; у `DECOR.gapS` числа нет нарочно.
- **Новый цвет обязан быть отнесён** к `DECISION_KEYS` или `BACKGROUND_KEYS` в
  `js/theme.js` и задан во ВСЕХ зонах, включая те, где форма не встречается:
  забытый ключ даёт `undefined` в `fillStyle`, и Canvas молча не рисует.
- **Фон держится ниже проёма по светлоте** на `GAP_GUARD = 0.25`. Светлячки —
  главный риск этого правила: «светящийся» и «темнее проёма» надо совместить.
- **Правка кода и правка документации едут ОДНИМ изменением**; «Разбор:» в коде
  и «Код:» в теме сверяются тестом в ОБЕ стороны.
- **Новый CSS обязан получить сторожа** — вывод этапа 1, где два отказа класса
  «функция не работает вовсе» прожили 953 проверки незамеченными. На этом этапе
  CSS не правится вовсе; если правка появится, сторож обязателен.
- **Исторические имена не переименовываются** («звёзды» в коде — кольца на
  экране).
- **Списки офлайн-кэша и версия ГЕНЕРИРУЮТСЯ** (`node tools/make-sw.mjs`).
- **Каждый этап кончается код-ревью, и это часть этапа:** прогон обоих наборов
  → ревью → правки по найденному → документация → коммит.
- **Не больше четырёх параллельных процессов**; оба набора — короткие
  однопоточные скрипты, запускать по одному.

## Review Focus

Пять входов, которые спек подразумевает, но ни одна задача не обязана была бы
проверить сама. Каждая строка получает тест в задаче-владельце.

1. **Звук выключен в родительском меню (`sound: 0`), а призы открыты** — не
   должно звучать НИЧЕГО, и подмена мотива не вправе обойти эту проверку.
   → Задача 1.
2. **Приз не открыт, варианта нет** — `play('star', {})` обязан сыграть базовый
   мотив, а не промолчать: `MOTIFS[undefined]` даёт `undefined`, и `play`
   выходит молча, то есть сбор кольца потерял бы звук совсем. → Задача 1.
3. **Состав видов обочины не может стать пустым.** `pickFrom` делит на сумму
   весов: при нулевой сумме выходит `NaN` и возвращается последний вид
   списка — то есть отбор по призу, оставивший зону без безусловных видов,
   даёт обочину из одного вида и не падает, а врёт. → Задача 2.
4. **Светлячки открыты, но зона не ночная** — светлячков нет: приз принадлежит
   одной зоне, и «открыт» не значит «везде». → Задача 3.
5. **Ободок у далёкого кольца**, где внутреннее отверстие не рисуется
   (`w <= 2.5`) — третий контур там тоже не рисуется: иначе далёкое кольцо
   становится дороже и превращается в пятно. → Задача 4.

Таблица вариантов и отбор — рядом с `play`:

```js
/* Приз подменяет мотив СОБЫТИЯ, а не добавляет новое событие. Таблица одна и
   здесь: иначе «какой приз что подменяет» разъехалось бы между звуком и
   лестницей. Разбор — docs/trophy-and-worlds.md. */
export const VARIANTS = {
  star: { chime: 'starChime' },
  finish: { fanfare: 'finishFanfare' },
};

/** Какой мотив играть с этим набором призов. Чистая функция — проверяется из
    node, где Web Audio нет вовсе. Неизвестный приз и закрытый приз дают
    базовое имя: `play` на несуществующем мотиве выходит молча, и сбор кольца
    потерял бы звук совсем. */
export function motifNameFor(name, prizes = {}) {
  const варианты = VARIANTS[name];
  if (!варианты) return name;
  for (const [приз, мотив] of Object.entries(варианты)) {
    if (prizes[приз] && MOTIFS[мотив]) return мотив;
  }
  return name;
}
```

Сам `play` — второй параметр и отбор. Проверка выключенного звука остаётся
ПЕРВОЙ строкой: приз не вправе её обойти.

```js
export function play(name, prizes = {}) {
  const vol = settings.get('sound') ?? 0.8;
  if (!vol) return;                 // «выключен» в родительском меню
  const c = wake();
  if (!c || c.state !== 'running') return;

  const имя = motifNameFor(name, prizes);
  const motif = MOTIFS[имя];
  if (!motif) return;
  const gain = vol * (LEVEL[имя] ?? 0.2);
  const t0 = c.currentTime + 0.005;
  const shape = имя === 'hit' ? 'sawtooth' : 'triangle';
  for (const [freq, offset, dur] of motif) note(t0 + offset, freq, dur, gain, shape);
}
```

```js
     список видов (отдельный «цветущий») разъехался бы с основным молча,
     поэтому владелец один — `kindsFor(zone, prizes)`, а приз правит ВЕС, а не
     состав. */
  check('без приза состав тот же, что в теме',
    kindsFor('greenHill').length === THEME.greenHill.decor.kinds.length);
  check('приз не добавляет и не убирает видов в зелёной зоне',
    kindsFor('greenHill', { bloom: true }).length === kindsFor('greenHill').length,
    'цветущая обочина — это ВЕСА, а не новые формы');

  /* Цветок и куст дешевле пальмы (2 заливки против 3), поэтому цветущая
     обочина кадр не утяжеляет, а облегчает. Проверяется это не на глаз:
     суммарная «цена» состава при призе обязана быть не выше, чем без него. */
  const ЦЕНА = { palm: 3, bush: 2, flower: 2, cactus: 2, spruce: 2, post: 2, totem: 2, rock: 1 };
  const средняя = (zone, prizes) => {
    const ks = kindsFor(zone, prizes);
    const сумма = ks.reduce((s, k) => s + k.weight, 0);
    return ks.reduce((s, k) => s + (ЦЕНА[k.kind] ?? 2) * k.weight, 0) / сумма;
  };
  for (const z of ZONES_ALL) {
    check(`зона ${z}: цветущая обочина не дороже обычной`,
      средняя(z, { bloom: true }) <= средняя(z) + 1e-9,
      `${средняя(z, { bloom: true }).toFixed(3)} против ${средняя(z).toFixed(3)} заливок на вид`);
  }
  check('и в зелёной зоне она ощутимо дешевле',
    средняя('greenHill', { bloom: true }) < средняя('greenHill') - 0.05,
    'именно этим и платится ободок — приз пятого уровня');

  /* Пустой состав невозможен ни при каком наборе призов. `pickFrom` делит на
     сумму весов: при нуле выходит NaN, возвращается последний вид списка — то
     есть обочина не падает, а ВРЁТ, и поймать это глазами нечем. */
  for (const z of ZONES_ALL) {
    for (const prizes of [{}, { bloom: true }, unlockedAt(1200)]) {
      const ks = kindsFor(z, prizes);
      check(`зона ${z}: состав не пуст при наборе ${JSON.stringify(Object.keys(prizes)).slice(0, 20)}`,
        ks.length > 0 && ks.reduce((s, k) => s + k.weight, 0) > 0,
        'нулевая сумма весов даёт NaN в pickFrom и обочину из одного вида');
    }
  }
```

```js
/* Состав видов обочины для зоны — с учётом открытых призов. Единственный
   владелец: `makeDecor` берёт виды только отсюда.

   Приз правит ВЕС, а не список: второй список («цветущий состав») разъехался
   бы с основным молча, и зона получила бы кактус там, где его нарисовать
   нечем. Поэтому у вида есть необязательное поле `bloomWeight` — вес при
   открытом призе, — и необязательное `needs`: имя приза, без которого вида в
   составе нет вовсе.

   Виды с `needs` ВСЕГДА отбираются поверх безусловных, и безусловный вид в
   зоне обязан остаться хотя бы один: `pickFrom` делит на сумму весов, и при
   нуле отдаёт последний вид списка — то есть обочина из одного вида, без
   всякого отказа. Это проверяется тестом по каждой зоне и каждому набору. */
export function kindsFor(zone, prizes = {}) {
  const kinds = THEME[zone]?.decor?.kinds || THEME[zonesOf()[0]].decor.kinds;
  const out = [];
  for (const k of kinds) {
    if (k.needs && !prizes[k.needs]) continue;
    const weight = prizes.bloom && k.bloomWeight != null ? k.bloomWeight : k.weight;
    if (!(weight > 0)) continue;
    out.push({ ...k, weight });
  }
  return out;
}
```

```js
  /* Ободок — третий контур кольца, и это ЕДИНСТВЕННЫЙ приз этапа, который
     добавляет заливку. Оплачен он Задачей 2 (цветущая обочина сместила вес с
     пальмы на цветок), и порядок тут обязателен: сначала плата, потом
     покупка. */
  const кадрКольца = (prizes) => paintFrame({
    stars: [{ x: 0, z: 3, worth: 1, taken: false }], elapsed: 0, prizes,
  }).fills.length;
  check('без приза ободка нет', кадрКольца({}) === кадрКольца({ rim: false }));
  check('с призом заливок ровно на одну больше',
    кадрКольца({ rim: true }) === кадрКольца({}) + 1,
    'ободок — один контур, а не два');

  /* У ДАЛЁКОГО кольца ободка нет. Там не рисуется и внутреннее отверстие
     (`w > 2.5`): на таком размере контуры сливаются, и третий превратил бы
     кольцо в пятно — заплатив при этом заливкой за каждое кольцо в глубине
     кадра, то есть ровно там, где их больше всего. */
  const кадрДалёкого = (prizes) => paintFrame({
    stars: [{ x: 0, z: 26, worth: 1, taken: false }], elapsed: 0, prizes,
  }).fills.length;
  check('у далёкого кольца ободка нет',
    кадрДалёкого({ rim: true }) === кадрДалёкого({}),
    'на таком размере контуры сливаются в пятно, а платить пришлось бы за каждое');
```

- [ ] **Step 3: Реализовать в `js/view.js`**

В `drawStars`, заменить последнюю строку отрисовки кольца:

```js
        ring(w, r, colr);
        if (w > 2.5) ring(w * 0.42, r * 0.42, colDim);
```

на:

```js
        ring(w, r, colr);
        /* Ободок — приз пятого уровня. Третий контур между телом и
           отверстием, тем же тёмным цветом: собственного цвета кольцу не
           положено, оно в контракте светлоты как цвет РЕШЕНИЯ.

           Под тем же порогом `w > 2.5`, что и отверстие: у далёкого кольца
           контуры сливаются, и третий превратил бы его в пятно — заплатив
           заливкой за каждое кольцо в глубине кадра, где их больше всего.

           Оплачен цветущей обочиной (приз уровня 2): она сместила вес с
           пальмы в 3 заливки на цветок и куст в 2. Порядок обязателен —
           сначала плата, потом покупка. */
        if (w > 2.5) {
          if (prizes.rim) ring(w * 0.70, r * 0.70, colDim);
          ring(w * 0.42, r * 0.42, colDim);
        }
```

**Порядок важен:** ободок рисуется ДО отверстия, иначе отверстие окажется под
ним и кольцо станет сплошным тёмным пятном в середине.
